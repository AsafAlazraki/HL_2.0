# Decisions

Dated one-liners. Each names what lost, so nobody re-argues it without new evidence.

## 2026-09-16

- **Rebuild from scratch, not refactor.** HL_Playground's engine is good (2,974 passing tests); its interface and working method are not. Lost: another redesign pass on the old tree (five had been rejected on sight).
- **Nothing visual or rule-like comes from the old repo.** No stylesheet, token ramp, font, tile rule, entry frame, `.tsx`, CLAUDE.md constitution, px ratchet or lint baseline. Lost: "reuse the design system to move faster".
- **Local-first, backend-ready.** Dexie behind `src/data/repository.ts`; Supabase is Milestone 6 as an adapter. Lost: Supabase from day one (single user today; the seam costs nothing).
- **The repo is public and the full seed is committed**, cost columns included. Lost: a private repo or a redacted seed (the old repo already publishes it; the owner accepted).
- **Selling flow first.** Entry, home, picker, place, configurator, cascade, document, quotes register; then Cockpit. Lost: breadth-first.
- **Directions first, per major screen, after a reference sweep.** Two or three static directions on real seed content; the owner picks. Lost: build-then-review.
- **Imagery is a first-class workstream** with provenance for every picture. Lost: "pictures later".
- **The original HelmLogic's modules (with marks and heroes), organisation and user management, and document templates are in scope** (Milestones 4–5). Lost: leaving them on the later list.
- **Tailwind 4 with `@theme` tokens** for styling, with per-screen CSS for bespoke work. Lost: plain CSS with cascade layers (all three design proposals preferred it for guard reasons; a one-row swap if the owner prefers).
- **`@base-ui/react` 1.8** for headless primitives, not the older `@base-ui-components/react` release candidate.
- **The packer is Node (`tsx`) importing the old repo's committed `buildNorthsideProject()`.** Python is not installed on this machine; the committed TS seed is byte-reproducible from the extracts, so packing from it loses nothing. Lost: porting the Python generator.
- **Deterministic ids**: table = seed key, row = `key:ordinal`, field = column key. Lost: minted nanoids that would not survive a Postgres import.
- **`freeze.ts` and `pairs.ts` are ported near-verbatim with an injected `Ctx`**, never rewritten. Three judges were unanimous: re-deriving the freeze is where a settled number or refusal gets lost.
- **Quotes change through commands with inverses and `QuoteEvent`s**; an issued quote refuses with a sentence. Lost: mutators on the store.
- **The cascade is a route** (`/quote/$id/cascade?fix=&from=`), so Back, refresh and a shared link behave.
- **One configurator that contains Address.** Lost: two generations behind a hash switch.
- **`priceLevels` are declared per table by the packer.** No Northside column name lives in app code.
- **Chapters ARE the quote's sections**; `buildSteps` derives them from the frozen document. A direction that needs a chapter with nothing behind it draws from the frozen specs and colourways, never by widening the model.
- **`fitmentCascade` is the only cascade builder without a caller in the old repo; Milestone 1 wires it.**
- **The sixteen workbook rules are all blocked on the seed and are carried as data with their measured rates.**
- **A sheet wipe never clears quotes.** A quote is a photograph of what was offered on the day. A separate, explicit "forget everything" in Admin does.
- **No boot-time migrations or adoptions.** A fresh schema with `orgId` on every record and one versioned pack needs none; the first one added is a design smell to argue about.
- **Light theme only until a theme is first-class.** The old toggle produced a light app with dark scrollbars.
- **Sign-in is a name until Milestone 6.** A password that protects nothing is fake data.
- **Ports live in `tools/ports.ts`** (dev 5100, preview 5101). Lost: a port per config file.
- **The scaffold was hand-written.** `npm create vite` cancels itself on a non-interactive shell; the files are the same ones it would have written.
- **Four cost names the old repo never flagged are cost columns in the pack**: `Total Nett CTD` (the workbook's own "true cost"), `Settlement` and `Discount` (two deductions in the dealer's buy ladder, not a customer discount), and `GP` (gross profit, in every spelling). 24 columns across eleven tables were reaching every surface that trusts `costColumns`; 139 are now named. `RRP` and `Sell` stay visible: they are the customer's prices. Evidence in `tools/seed/levels.ts` and `docs/reference/MPF_GROUND_TRUTH.md`. Lost: porting the old list verbatim and calling it safe.
- **The seed's held pictures are 12.1 MB after fetching 109 more addresses** (329 held, 118 unheld, 6 refused). The old repo pinned a 12,000,000-byte ceiling in a test and said whoever crosses it must decide about size first; HL_2.0 carries no such ceiling. The owner decides if a smaller long edge or quality is wanted; nothing is discarded meanwhile.

## 2026-09-17

- **Stage pictures are a second tier, fetched at stage size.** `public/seed-images` stays capped at long edge 1100, which is right for a row or a tile; `public/hero-images` holds the few pictures that fill a window, at long edge 2560, chosen in `data/northside/heroes.json` and recorded in `heroes-ledger.json`. Measured: of 329 held catalogue copies only 39 reach 1100px, and the Stacer 529 Assault Pro's on-water photograph is 1024×676 because the address the price file carries is itself a WordPress resize. Drawing a stage from those meant upscaling. Lost: one tier for everything.
- **A hero cannot be chosen automatically, and the code now says so.** The scene/studio judge answers "is this a render on a white ground", not "is this a wide shot of the whole boat". Picking the largest verified photograph for four Stacer models returned a transom on white, a seat locker, a floor locker and a steering console: right model, right source, wrong picture. `tools/seed/pick-heroes.ts` now reads the maker's own file name first (Stacer marks on-water frames "Lifestyle" or "EXT" and cabin frames "INT" or "Internal"), keeps the judge as a second gate, and every pick was looked at on a contact sheet before it was kept. Lost: trusting a label.
- **Stacer publishes its on-water photography at web size.** Its lifestyle frames are mostly 1180×600; the widest are the 519 Sea Ranger at 3000×1985 and the 481 SeaMaster at 1771×1183. Highfield's media library, by contrast, carries 5,000 to 9,500 pixel originals per model. So a photographed direction drawn on a Highfield fills a window and one drawn on most Stacers does not, and a board must say which it is standing on.
- **Customisation is a first-class requirement, and bounded.** The owner: "things should be so dynamic so users can control everything and set their own backgrounds… full massive customisability". Every token is already emitted to `:root` under `@theme static`, so an organisation layer and a person layer override by setting the same custom properties at boot; no screen reads an appearance record. Every choice is measured rather than hoped: a chosen photograph gets a scrim computed from its own pixels, a chosen colour is checked against the ground it will sit on, and a choice that cannot hold contrast is refused with a sentence and the nearest thing that works. Not settable: anything that puts cost on a customer surface, the refusal sentences, the price figure's behaviour, the contrast floor. Written up in `docs/CUSTOMISATION.md`. Lost: a settings page bolted on at the end, and an unbounded page builder (named as an open question for the owner).
- **Responsive on every screen size, and it is measured, not promised.** The owner, 2026-09-17: "reminder that responsive on EVERY screen size". The plan had promised only that "phone width does not break" in Milestone 1, with tablet and phone parity deferred to Milestone 2. That is now wrong: every ruler runs at six viewports — phone 390×844, phone landscape 844×390, tablet 834×1112, laptop 1280×800, desktop 1440×900 and wide 1920×1080 — so a layout that only holds at the size it was drawn at fails in CI rather than in front of a customer. Playwright's own device presets are not used: `Pixel 7` carries a 2.625 pixel ratio, which breaks the screenshot determinism recipe a ruler asserts, and `iPad (gen 7)` selects WebKit, which this project does not install. Each project states its own viewport on Chromium and whether it is a touch screen. Measured on this change: 32 checks pass across all six. Lost: treating small screens as a later pass.
- **Brand marks are held, with the two gaps named rather than filled.** The home sweep flagged `public/brand-marks/` as an outright blocker: no board could draw a brand shelf. `tools/seed/marks.ts` now holds seventeen files covering twelve of the thirteen brands the seed carries, chosen from what the imagery sweep verified live, SVG where the maker publishes one. Two rules earn their place. A candidate whose file name says badge, series or heading is refused, because Mackay's "KRX-Badge-01" and Dunbier's "SupaRolla" are product names, not marks. And a raster mark is measured rather than trusted: Mercury publishes exactly one mark, calls it a footer logo, and every opaque pixel in it is pure white, so filed as the dark variant it would have shipped as an invisible logo on a white page. It is filed as `mercury-white` and the absence of a dark one is recorded. Stabicraft publishes nothing but a 180px touch icon, so it has no mark and a screen that wants one says the name in type. Every pick was looked at on a contact sheet. Lost: trusting a file name.
- **One comparator, and the solver now uses it.** `src/domain/rules/configure/values.ts` carried a second copy of the rule engine's ordering with a comment saying it "deliberately mirrors" the first; the copies had already drifted, because the engine learned to read a measurement ("10 HP" is ten horsepower) and the solver's copy had not. So the configurator's preview pruned values the run would have kept, on the exact column the defect was measured on. `compare` now delegates to `@/domain/compare` and keeps only what is genuinely its own: the three-valued answer (a `mismatch` on the shared comparator is `undefined` here, which is what lets a rule fail open) and the two image cases (an empty picture list reads as blank, a non-empty one orders against nothing). Pinned by `configure/sameComparator.test.ts`. Lost: two copies kept in step by hand.
- **The nine places are minted when the pack lands, and their ids are derived from their names.** A module name is a business string, so the plan keeps the places out of the data; `@/data/pack/boot` is the app's one caller of `mintModules`, and `src/test/fixtures/pack.ts` is the other, so a suite and the browser see the same nine. The id is `place:` plus the slug of the name rather than a fresh one, because a sheet wipe keeps the quotes and the file then lands again underneath them — a quote that named a place must not find nothing where it looked. Stamped with the pack's own `packedAt`, so a second landing writes identical records. Lost: a fresh id per load, which is what the old store action minted.
- **`meta` still means "the whole sheet is down there".** The pack's tables land one transaction each, then the places, and only then is `CatalogueMeta` written — so a browser closed at the wrong moment comes back to a sheet it knows is incomplete rather than to one with no doors and nothing saying so. And a failed WRITE is not a failed READ: the sheet is handed to the store anyway with the sentence beside it, because a private window or a full disk does not make the 15,691 rows that were just read wrong. Only the speed of the next open is lost. Proven end to end in `src/data/pack.dexie.test.ts` and in the browser by the second `pack-loads` flow, which counts the JSON requests a reload makes: zero.
- **`src/domain/index.ts` names the doors, not the folder.** One published entry point per area with the types its answers come in, and three words deliberately left unpublished because two areas answer different questions with them (`buildGroups`, `optionsOf`, and discovery's own `Candidate`/`Verdict`, which the contract already owns). Importing from the barrel is never required and nothing inside `src/domain` does it. Lost: `export *`, which is a second copy of the folder listing and a cycle waiting to happen.
- **A test moves with its subject.** The three "registry seams" cases in `rules/adopt.test.ts` drove `constraintDefs` as a module-level registry mirrored in browser storage, which `src/domain` cannot have; they now stand in `rules/constraints/deleteRule.test.ts` against the pure API, under the same name, with the same assertions word for word and a fourth beside them. `adopt.test.ts` carries the note saying where they went. Lost: keeping a passing copy in both files, which is two answers to one question again.
- **A dropped test is a defect, and six of them were dropped.** The round-1 critique counted node suites folder by folder against `HL_Playground` and found six that came across as nothing at all, with no note anywhere saying so — `issue.test.ts` (19), `link.test.ts` (19), `moduleBlocks.test.ts` (11), `newRule.test.ts` (19), `referenceDay.test.ts` (6) and `quoteTerms.test.ts` (5). Two of the six left plan-named modules with no coverage whatsoever: eight of `totals.ts`'s ten exports and all four issue-blocker sentences, and `freezeCustomer`/`customerBook`/`hasCustomerRegister`/`fileCustomer`. All six are in the tree now. Of their 79 cases, 70 came across with their assertions word for word; four could not, every one an assertion about `ensureCustomerRegister` — five project-store writes collapsed into one history step, which is M2 — and they are named in `src/state/customerLink.test.ts` with what they wait on. The remaining five are `quoteTerms`, and they are the one suite in this round whose assertions had to be rewritten rather than moved: what it drove was `useProjectStore.setQuoteTerms`, and the behaviour now lives at the mint, where `freeze.ts` copies `ctx.org.quoteTerms` onto the document. Its header says exactly that, and names the two promises that belong to the admin screen instead. Lost: the idea that a suite whose subject changed shape may be left behind quietly.
- **A store-backed suite is ported, never dropped: the registry becomes a shim, a context or the store itself.** Three different answers, one rule. `issue.test.ts` drove a module-level quote registry, so the six registry calls are re-created over `apply` at the top of the file in nine lines and every test body is the old one unchanged. `link.test.ts` drove the project store and the registry at once, so it sits in `src/state` — the one place that may import both — with the four catalogue writes expressed as the next `CatalogueCtx`. `moduleBlocks.test.ts` drove `createModule` over the demo seed, so it reads `loadPack()` and calls the same `defaultBlocksFor` the store action called; every figure the old file measured is still true — Stacer 4, Stabicraft 6, Surtees 5, Jeanneau 6, Haines 3, Highfield 6, Formosa 4. Lost: "it needs a store, so it cannot be ported".
- **`nthToday` came back, and nothing could mint a reference without it.** It was the one export of the old `quotes.ts` with no caller in the new tree, so `mintQuote` demanded a `reference` that no code could compute — and the timezone defect it guards, two halves of `20260818-01` reading two different calendars at UTC+10, had no test at all. It is `freeze.ts:nthToday(quotes, day)` and `referenceForNow(quotes, at)` now: the registry arrives as an argument and the instant is read exactly once, which is the property the old function took `new Date()` itself to protect. Lost: a pure module calling the clock.
- **`vitest/expect-expect` is off for four named files, not for every test in the repo.** It had been off repo-wide to accommodate ported suites whose assertions the rule cannot see statically — through a helper (`expectPreviewMatchesQuote`, `roundTrip`) or inside a loop over the real pack. Off everywhere, a test that asserts nothing at all passes the linter in silence, which is the shape of hollow test this whole port exists to prevent. Lost: one line of config in exchange for a blind spot over 143 files.
- **Four dependencies were floating on `"*"` and are now pinned to what the lockfile holds** — `lucide-react` ^1.46.0, `@testing-library/{jest-dom,react,user-event}` ^7.0.1/^16.3.3/^14.6.7. CI runs `npm ci && npm test`; with a star spec, the next `npm i` would have floated any of the four and the gate would have been measuring a different tree than the one that was green. Lost: nothing — the resolved versions did not move, and `npm ci --dry-run` agrees.
- **Every motion value names its source, because four numbers in a cubic-bezier carry no provenance.** The round-2 audit found three easing tokens in `src/styles/tokens.css` byte-identical to `HL_Playground/src/styles/system.css` — same three names, same order — with the duration ladder beneath them the old `D_PRESS/D_FAST/D_MED/D_SLOW` renamed. Nothing in the file said where they came from, so a reader could not tell a curve chosen from a published spec from one lifted off the old ramp, and the standing rule is that nothing rule-like crosses. The curves and the ladder are now Material Design 3's published motion tokens, each line naming the token it is (`md.sys.motion.easing.standard`, `.legacy`, `.emphasized.decelerate`, and short2/short3/short4/medium2 for 100/150/200/300 ms), so the check is against the spec rather than against this file. `src/ui/motion.ts`'s springs were 0.16/0.2/0.26 — the same old ladder in seconds — and are now the same three durations as the CSS, one ladder with one citation. The focus ring keeps its two-ring recipe and now says why: WCAG 2.2 SC 2.4.13 wants 2px at 3:1, which a single ring cannot promise against an unknown ground. Lost: values that were probably fine and could not be shown to be.
- **Three suites deferred one property to the same absent screen, so the property was built instead.** `constraints/tenantKey.test.ts` (14), `store/undo.test.ts`'s "when the business was set up" (4) and `quote/quoteTerms.test.ts`'s "SURVIVE A RENAME" (1) were each about one sentence — *what a business wrote is still there after it changes what it is called* — and each was pushed onto the admin screen that types the organisation, which does not exist. Nothing in 2,267 tests measured it. The act is `src/domain/people/organisation.ts` now: `setOrganisation` and `setQuoteTerms` as pure functions over the profile, with the old store action's argued comments intact and the clock injected. Fourteen cases in its suite. Ten of `tenantKey`'s cannot ever come across and the file says so — they drive `orgKeyOf`, `legacyOrgKeyOf` and `adoptSlugKey`, and `orgId` on every record retires all three (and "no boot-time migrations" retires the fourth). Lost: a fourth deferral.
- **`keepingOrganisation` put back two of the profile's five fields, and the port was faithful to that.** The old wrapper called `setOrganisation(keep.name, keep.industry)` into an action that fell back to `meta.org?.createdAt` — which the `replaceProject` it was wrapping had just deleted. So the one function written to make a project swap invisible re-dated the business to the moment of the swap, re-derived the tenant key off whatever the business is called today, and dropped the dealership's standing quote terms: TENANCY §4.6 happening inside the single caller the rule was written for. `ApplyPorts.setOrganisation` now takes the whole `OrgProfile`, which is the only shape that cannot forget a field. The memory harness was hiding it — its `replaceProject` kept the profile, so the wrapper would have passed whether or not it put anything back — and now clears it exactly as the store does. Four cases in `src/domain/io/keepOrganisation.test.ts`. Lost: a port so faithful it carried the defect and no test.
- **Two more guards, and both close a hole rather than measure tidiness.** `domain-is-pure` matches import lines, so `document.querySelector` or `new Image()` written inside a domain function passed it — the plan put the globals on the agent, which holds for one port and not for the many sessions that will touch `src/domain` next. `domain-touches-no-dom` reads the masked source the way the two text rules do, so a comment explaining the constraint does not trip it. And `source-is-text` refuses a raw U+0000 or a CRLF line ending: `HL_Playground/src/features/search/encoding.test.ts` records a `.tsx` that carried three NUL bytes and 931 CRLF lines while `tsc`, 1,914 tests, the linter and the style checker were all green, because a NUL in a template literal is a valid separator — it only broke `grep` and git's `text=auto`. `.gitattributes` and `prettier --check` cannot see it. Thirteen rules now, every one with a fixture test; `data/` is out of the text rule's scope on purpose, being 11 MB nobody types. Lost: a guard set that could not see the one defect class that had already shipped once.
- **"Nothing from the old design system" is now a guard, not a promise.** It was in the brief of every agent that has touched this repo and it was broken anyway: three easing tokens in `src/styles/tokens.css` were byte-identical to `HL_Playground/src/styles/system.css:820-822`, same names, same order, found by the second Milestone 0 critic. The first fix replaced one of them with a curve that is a real declaration in the old repo's `ds.css:518` under the same name, which the new guard caught immediately. `tools/check/oldSystem.ts` reads every authored value in the old repo's stylesheets — curves, shadows, gradients, font stacks, 67 of them — and refuses any that reappears in ours. It compares values, not names, because `--ease-out` is a name anyone would pick and `cubic-bezier(0.23, 1, 0.32, 1)` is a decision somebody made. Values nobody could choose differently are never compared. One narrow exemption exists as an auditable list: a published standard is not the old repo's decision even when the old repo cited it too, so a value may pass only when it is named in `CITED` with the spec it comes from, and a test holds that list to eight. If the old repo is absent the rule finds nothing and passes; a clone on a fresh machine must still build. Lost: trusting that a rule in a brief is a rule.
- **A ruler is a module the app walks and a fixture page proves.** The five rulers each guarded their own non-vacuity (`expect(r.measured).toBeGreaterThan(0)`) and none of them could be shown to find a defect: the measuring functions were closures passed to `page.evaluate`, unexported and unimportable, so the contrast sweep's five hard-won corrections — the `color(srgb …)` parse, the browser-side oklch conversion, compositing the WHOLE ancestor chain, compositing translucent text, and a leaf being "an element with a text node of its own" — were arithmetic nobody had watched fail. On one placeholder route with two measurable text nodes, a parser returning white for every colour would have reported the same clean green. Each measurement is now its own module under `e2e/rulers/measure/`, moved with every line of its reasoning, and `e2e/rulers/fixture.spec.ts` points all five at pages built to fail one named way at a time: known ratios (2.85, 1.4 through two tints, 3.98 composited), a planted overlap beside its three exemptions, a cut beside an elision on both axes, tokens declared inside an `@media` so the recursive rule walk is exercised, and twenty rows in view beside one below the fold. Lost: "it guards that it measured something", which is the floor, not the proof.
- **A guard says how many files it read, and reading none is a failure.** `no-cost-column-in-a-screen` — the rule that keeps cost and margin off a customer's page, the honesty CLAUDE.md states first — was scoped to `src/screens/`, which does not exist on this tree. It read zero files while `check` printed `14 rules, no failures`, and its fixture test could not see that, because a fixture hands a rule a fabricated `src/screens/…` path and passes either way. Only a walk of the real tree knows. So `runRules` returns a per-rule file count, `tools/check.ts` prints every rule with its count and exits non-zero on any rule that read nothing, and a suite in `rules.test.ts` runs the same walk. The scope of both surface rules is now every folder that renders — `src/screens/`, `src/routes/` and `src/ui/` — because the plan's own layout puts the quote DOCUMENT at `routes/quote.$id.document`. Lost: a fixture test taken as proof that a rule is pointed at something.
- **The hero and brand-mark ledgers are measured the way the image ledger is, and the bytes are hashed.** `images.json` had 8 suites over it; `heroes-ledger.json` and `marks-ledger.json` had none — nothing in src, tools or e2e read either file except the scripts that write them. So nothing asserted that a hero's file is on disk, that a mark's artwork is the artwork recorded, or that a hero's `table` and `model` resolve to a real row, which is CLAUDE.md's "a picture belongs only to the exact model it depicts" stated as arithmetic. `src/data/imagery.test.ts` is 13 cases over both: every entry accounted for one-for-one against the folder, every recorded `sha256` recomputed from the bytes on disk, no hero larger than the source it came from, every hero's model found in its table's display field, every mark's brand named by a table or by a row of the price file, and the one refused mark carrying a measured reason with no stand-in. Lost: provenance that was true when a person last looked.
- **`no-old-design-system` reads code as well as stylesheets, and the run says how much evidence it had.** The round-2 defect had two halves — three easing tokens in `tokens.css` AND `src/ui/motion.ts`'s springs, the same ladder in seconds — and the rule as written saw only `.css`. It now also searches `.ts`/`.tsx` under `src/` for the old values as literal strings, which is the shape a curve takes when it is lifted into a transition template; test files are out of reach, because the fixture that proves this rule fires has to fabricate an old value. And because CI runs on ubuntu-latest where HL_Playground has never existed, the rule is silent there on every run: `tools/check.ts` now prints how many old values it compared against and from where, so "compared 67 values" and "compared none" are different lines rather than the same green tick. Lost: a guard that could go dark without anybody noticing.
- **A refusal is reachable, and that is asserted rather than inherited from a library.** `Menu` and `Select` proved only that a refused item CARRIES its sentence (`toHaveAccessibleDescription`), which is a DOM fact; whether a keyboard can land on the item — the thing that makes the sentence audible — rested on two Base UI internals (`useMenuItem`'s `focusableWhenDisabled`, `SelectRoot`'s empty `disabledIndices`). "Base UI APIs move — each wrapped once in `src/ui`" is the plan's own reason for the wrappers, so a minor bump could turn the refusal silent on exactly the control a dealer meets it on with the suite green. Both suites now walk the arrows onto the refused row, assert focus lands there, and assert it still refuses to act. Lost: a behaviour guaranteed by someone else's implementation detail.
- **A guard that reads no files now fails, because a fixture test structurally cannot see that.** The round-3 critic found `no-cost-column-in-a-screen` scoped to `src/screens/`, a folder that does not exist on this tree, so the guard protecting "cost and margin never reach a customer-facing surface" read zero files — and the run printed `check: 14 rules, no failures`, which is exactly what it prints when fourteen rules have really looked. A fixture hands the rule a fabricated `src/screens/…` path, so it passes either way; only a walk of the real tree knows. `runRules` now returns a per-rule file count, the run prints it, and `blindRules` turns "read nothing" into a failure with its own fixture. The cost rule went from 0 files to 34. Lost: trusting that a green guard looked at anything.
- **The five rulers now have a page built to fail in front of them.** `e2e/rulers/fixture.spec.ts` points each measurement at a known defect and watches it come back. Each ruler already guarded its own non-vacuity, but on a tree with one placeholder route "0 below threshold" is also what a silently broken parser returns. The measurement half of each ruler moved into `e2e/rulers/measure/` so the fixture can drive it directly. Lost: a ruler that has never been seen to fail.
- **The owner handed the design decisions over: "go for what u think is awesome and build literally everything please before i review it" (2026-09-17).** So every remaining Milestone 1 screen is researched, given directions, decided here and built, without stopping for a pick. The boards are still drawn and kept, because they are the record of what was considered and the thing he can point at to change his mind cheaply; what changes is that the recommended one is built immediately and the screen is marked **provisional** in `docs/SCREENS.md` until he has looked. Nothing else relaxes: the sweep still precedes the board, the board still cites its frames, the critic still judges the built screen, and no figure is ever invented. Lost: waiting.
- **The token set is the two picked boards, measured off them value by value.** `src/styles/tokens.css` was a placeholder written before any direction existed, and its own header said the first pick replaced it wholesale; entry B "Veil and card" and home B "Cinema day" are picked, so it is theirs now. Every value is cited on its own line as a byte off one of the two boards, or as a published spec (Material Design 3's motion tokens, WCAG 2.2 SC 2.4.13's focus ring), or as one of nine interpolations that say which two cited anchors they sit between. The neutrals are the boards' navy, hue 232 to 245, not grey; the blue means the file and nothing else (`--color-blue-600` is entry B's `#1A65BD` door); the amber is home B's act and has exactly the two steps that board draws. Where two board values sit closer than the eye reads them the comment names the one that folded, with the distance — the boards set 34 colours and 19 type sizes and a ramp cannot carry that. All 26 opaque colours are inside the sRGB gamut, read back through the cascade, which answers the provisional file's nine clamped blues; the four white lines are `rgb(255 255 255 / n%)` rather than `oklch(100% 0 0 / n%)` because the ramp ruler caught the latter resolving to 1.00007 and flagging itself outside the gamut. Lost: `--color-black`, `--radius-xl`, `--radius-2xl`, `--shadow-xs`, `--shadow-sm` and `--text-7xl`, which nothing reads and no picked board draws; and a mid-scale control border that clears 3:1 on white, which neither board has a value for and which is written down as measured rather than invented.
