# Decisions

Dated one-liners. Each names what lost, so nobody re-argues it without new evidence.

## 2026-09-16

- **Rebuild from scratch, not refactor.** HL_Playground's engine is good (2,974 passing tests); its interface and working method are not. Lost: another redesign pass on the old tree (five had been rejected on sight).
- **Nothing visual or rule-like comes from the old repo.** No stylesheet, token ramp, font, tile rule, entry frame, `.tsx`, CLAUDE.md constitution, px ratchet or lint baseline. Lost: "reuse the design system to move faster".
- **Local-first, backend-ready.** Dexie behind `src/data/repository.ts`; Supabase is Milestone 6 as an adapter. Lost: Supabase from day one (single user today; the seam costs nothing).
- **The repo is public and the full seed is committed**, cost columns included. Lost: a private repo or a redacted seed (the old repo already publishes it; the owner accepted).
- **Selling flow first.** Entry, home, picker, place, configurator, cascade, document, quotes register; then Cockpit. Lost: breadth-first.
- **Directions first, per major screen, after a reference sweep.** Two or three static directions on real seed content; the owner picks. Lost: build-then-review.
- **Imagery is a first-class workstream** with provenance for every picture. Lost: "pictures later".
- **The original HelmLogic's modules (with marks and heroes), organisation and user management, and document templates are in scope** (Milestones 4–5). Lost: leaving them on the later list.
- **Tailwind 4 with `@theme` tokens** for styling, with per-screen CSS for bespoke work. Lost: plain CSS with cascade layers (all three design proposals preferred it for guard reasons; a one-row swap if the owner prefers).
- **`@base-ui/react` 1.8** for headless primitives, not the older `@base-ui-components/react` release candidate.
- **The packer is Node (`tsx`) importing the old repo's committed `buildNorthsideProject()`.** Python is not installed on this machine; the committed TS seed is byte-reproducible from the extracts, so packing from it loses nothing. Lost: porting the Python generator.
- **Deterministic ids**: table = seed key, row = `key:ordinal`, field = column key. Lost: minted nanoids that would not survive a Postgres import.
- **`freeze.ts` and `pairs.ts` are ported near-verbatim with an injected `Ctx`**, never rewritten. Three judges were unanimous: re-deriving the freeze is where a settled number or refusal gets lost.
- **Quotes change through commands with inverses and `QuoteEvent`s**; an issued quote refuses with a sentence. Lost: mutators on the store.
- **The cascade is a route** (`/quote/$id/cascade?fix=&from=`), so Back, refresh and a shared link behave.
- **One configurator that contains Address.** Lost: two generations behind a hash switch.
- **`priceLevels` are declared per table by the packer.** No Northside column name lives in app code.
- **Chapters ARE the quote's sections**; `buildSteps` derives them from the frozen document. A direction that needs a chapter with nothing behind it draws from the frozen specs and colourways, never by widening the model.
- **`fitmentCascade` is the only cascade builder without a caller in the old repo; Milestone 1 wires it.**
- **The sixteen workbook rules are all blocked on the seed and are carried as data with their measured rates.**
- **A sheet wipe never clears quotes.** A quote is a photograph of what was offered on the day. A separate, explicit "forget everything" in Admin does.
- **No boot-time migrations or adoptions.** A fresh schema with `orgId` on every record and one versioned pack needs none; the first one added is a design smell to argue about.
- **Light theme only until a theme is first-class.** The old toggle produced a light app with dark scrollbars.
- **Sign-in is a name until Milestone 6.** A password that protects nothing is fake data.
- **Ports live in `tools/ports.ts`** (dev 5100, preview 5101). Lost: a port per config file.
- **The scaffold was hand-written.** `npm create vite` cancels itself on a non-interactive shell; the files are the same ones it would have written.
- **Four cost names the old repo never flagged are cost columns in the pack**: `Total Nett CTD` (the workbook's own "true cost"), `Settlement` and `Discount` (two deductions in the dealer's buy ladder, not a customer discount), and `GP` (gross profit, in every spelling). 24 columns across eleven tables were reaching every surface that trusts `costColumns`; 139 are now named. `RRP` and `Sell` stay visible: they are the customer's prices. Evidence in `tools/seed/levels.ts` and `docs/reference/MPF_GROUND_TRUTH.md`. Lost: porting the old list verbatim and calling it safe.
- **The seed's held pictures are 12.1 MB after fetching 109 more addresses** (329 held, 118 unheld, 6 refused). The old repo pinned a 12,000,000-byte ceiling in a test and said whoever crosses it must decide about size first; HL_2.0 carries no such ceiling. The owner decides if a smaller long edge or quality is wanted; nothing is discarded meanwhile.

## 2026-09-17

- **Stage pictures are a second tier, fetched at stage size.** `public/seed-images` stays capped at long edge 1100, which is right for a row or a tile; `public/hero-images` holds the few pictures that fill a window, at long edge 2560, chosen in `data/northside/heroes.json` and recorded in `heroes-ledger.json`. Measured: of 329 held catalogue copies only 39 reach 1100px, and the Stacer 529 Assault Pro's on-water photograph is 1024×676 because the address the price file carries is itself a WordPress resize. Drawing a stage from those meant upscaling. Lost: one tier for everything.
- **A hero cannot be chosen automatically, and the code now says so.** The scene/studio judge answers "is this a render on a white ground", not "is this a wide shot of the whole boat". Picking the largest verified photograph for four Stacer models returned a transom on white, a seat locker, a floor locker and a steering console: right model, right source, wrong picture. `tools/seed/pick-heroes.ts` now reads the maker's own file name first (Stacer marks on-water frames "Lifestyle" or "EXT" and cabin frames "INT" or "Internal"), keeps the judge as a second gate, and every pick was looked at on a contact sheet before it was kept. Lost: trusting a label.
- **Stacer publishes its on-water photography at web size.** Its lifestyle frames are mostly 1180×600; the widest are the 519 Sea Ranger at 3000×1985 and the 481 SeaMaster at 1771×1183. Highfield's media library, by contrast, carries 5,000 to 9,500 pixel originals per model. So a photographed direction drawn on a Highfield fills a window and one drawn on most Stacers does not, and a board must say which it is standing on.
- **Customisation is a first-class requirement, and bounded.** The owner: "things should be so dynamic so users can control everything and set their own backgrounds… full massive customisability". Every token is already emitted to `:root` under `@theme static`, so an organisation layer and a person layer override by setting the same custom properties at boot; no screen reads an appearance record. Every choice is measured rather than hoped: a chosen photograph gets a scrim computed from its own pixels, a chosen colour is checked against the ground it will sit on, and a choice that cannot hold contrast is refused with a sentence and the nearest thing that works. Not settable: anything that puts cost on a customer surface, the refusal sentences, the price figure's behaviour, the contrast floor. Written up in `docs/CUSTOMISATION.md`. Lost: a settings page bolted on at the end, and an unbounded page builder (named as an open question for the owner).
- **Responsive on every screen size, and it is measured, not promised.** The owner, 2026-09-17: "reminder that responsive on EVERY screen size". The plan had promised only that "phone width does not break" in Milestone 1, with tablet and phone parity deferred to Milestone 2. That is now wrong: every ruler runs at six viewports — phone 390×844, phone landscape 844×390, tablet 834×1112, laptop 1280×800, desktop 1440×900 and wide 1920×1080 — so a layout that only holds at the size it was drawn at fails in CI rather than in front of a customer. Playwright's own device presets are not used: `Pixel 7` carries a 2.625 pixel ratio, which breaks the screenshot determinism recipe a ruler asserts, and `iPad (gen 7)` selects WebKit, which this project does not install. Each project states its own viewport on Chromium and whether it is a touch screen. Measured on this change: 32 checks pass across all six. Lost: treating small screens as a later pass.
- **Brand marks are held, with the two gaps named rather than filled.** The home sweep flagged `public/brand-marks/` as an outright blocker: no board could draw a brand shelf. `tools/seed/marks.ts` now holds seventeen files covering twelve of the thirteen brands the seed carries, chosen from what the imagery sweep verified live, SVG where the maker publishes one. Two rules earn their place. A candidate whose file name says badge, series or heading is refused, because Mackay's "KRX-Badge-01" and Dunbier's "SupaRolla" are product names, not marks. And a raster mark is measured rather than trusted: Mercury publishes exactly one mark, calls it a footer logo, and every opaque pixel in it is pure white, so filed as the dark variant it would have shipped as an invisible logo on a white page. It is filed as `mercury-white` and the absence of a dark one is recorded. Stabicraft publishes nothing but a 180px touch icon, so it has no mark and a screen that wants one says the name in type. Every pick was looked at on a contact sheet. Lost: trusting a file name.
- **One comparator, and the solver now uses it.** `src/domain/rules/configure/values.ts` carried a second copy of the rule engine's ordering with a comment saying it "deliberately mirrors" the first; the copies had already drifted, because the engine learned to read a measurement ("10 HP" is ten horsepower) and the solver's copy had not. So the configurator's preview pruned values the run would have kept, on the exact column the defect was measured on. `compare` now delegates to `@/domain/compare` and keeps only what is genuinely its own: the three-valued answer (a `mismatch` on the shared comparator is `undefined` here, which is what lets a rule fail open) and the two image cases (an empty picture list reads as blank, a non-empty one orders against nothing). Pinned by `configure/sameComparator.test.ts`. Lost: two copies kept in step by hand.
- **The nine places are minted when the pack lands, and their ids are derived from their names.** A module name is a business string, so the plan keeps the places out of the data; `@/data/pack/boot` is the app's one caller of `mintModules`, and `src/test/fixtures/pack.ts` is the other, so a suite and the browser see the same nine. The id is `place:` plus the slug of the name rather than a fresh one, because a sheet wipe keeps the quotes and the file then lands again underneath them — a quote that named a place must not find nothing where it looked. Stamped with the pack's own `packedAt`, so a second landing writes identical records. Lost: a fresh id per load, which is what the old store action minted.
- **`meta` still means "the whole sheet is down there".** The pack's tables land one transaction each, then the places, and only then is `CatalogueMeta` written — so a browser closed at the wrong moment comes back to a sheet it knows is incomplete rather than to one with no doors and nothing saying so. And a failed WRITE is not a failed READ: the sheet is handed to the store anyway with the sentence beside it, because a private window or a full disk does not make the 15,691 rows that were just read wrong. Only the speed of the next open is lost. Proven end to end in `src/data/pack.dexie.test.ts` and in the browser by the second `pack-loads` flow, which counts the JSON requests a reload makes: zero.
- **`src/domain/index.ts` names the doors, not the folder.** One published entry point per area with the types its answers come in, and three words deliberately left unpublished because two areas answer different questions with them (`buildGroups`, `optionsOf`, and discovery's own `Candidate`/`Verdict`, which the contract already owns). Importing from the barrel is never required and nothing inside `src/domain` does it. Lost: `export *`, which is a second copy of the folder listing and a cycle waiting to happen.
- **A test moves with its subject.** The three "registry seams" cases in `rules/adopt.test.ts` drove `constraintDefs` as a module-level registry mirrored in browser storage, which `src/domain` cannot have; they now stand in `rules/constraints/deleteRule.test.ts` against the pure API, under the same name, with the same assertions word for word and a fourth beside them. `adopt.test.ts` carries the note saying where they went. Lost: keeping a passing copy in both files, which is two answers to one question again.
